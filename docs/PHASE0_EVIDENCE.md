## Build evidence integrity

Successful Android/iOS build bundles are validated with:

```sh
python3 scripts/verify_phase0_evidence.py \
  --root <extracted-build-evidence> \
  --platform android
```

Use `--platform ios` for iOS. The verifier rejects missing/unlisted files, size/SHA-256 mismatches, incorrect Flutter/Dart pins, identifier mismatches, malformed APKs, and malformed iOS simulator archives.

## Launch evidence integrity

Connected targets can produce independent launch evidence with:

```sh
./scripts/capture_android_launch_evidence.sh \
  --apk /path/to/clearscan-debug.apk \
  --output artifacts/phase0_launch/android
```

On macOS:

```sh
./scripts/capture_ios_launch_evidence.sh \
  --archive /path/to/clearscan-ios-simulator.zip \
  --output artifacts/phase0_launch/ios
```

Verify downloaded/extracted launch evidence with:

```sh
python3 scripts/verify_phase0_launch_evidence.py \
  --root artifacts/phase0_launch/android \
  --platform android
```

Use `--platform ios` for iOS. The launch verifier checks the launch-report schema, exact application identifier, artifact/screenshot hashes, PNG screenshot structure, native archive structure, and platform-specific runtime state.

## Hosted GitHub Actions evidence

The `Flutter quality gate` workflow contains four jobs:

1. `source-quality` - installs exact pinned Flutter, validates repository/source/evidence contracts, runs format/analyze/tests.
2. `native-android` - generates official runners, verifies identifiers, builds/verifies the debug APK, provisions an Android API 35 Google APIs x86_64 emulator, installs/launches the real APK, captures/verifies runtime evidence and screenshot.
3. `native-ios` - generates official runners on macOS, verifies identifiers, builds/verifies the simulator app, installs/launches the real app with `simctl`, captures/verifies runtime evidence and screenshot.
4. `phase0-summary` - always writes a single Markdown summary containing source result, build verifier flags/digests, launch verifier flags/screenshot digests, and the final gate-ready state.

## Downloaded hosted-run verification

After GitHub Actions finishes, do not trust the web UI or filenames alone. The supported collector is:

```sh
./scripts/run_phase0_github_gate.sh --repo OWNER/REPO --run-id RUN_ID
```

It downloads artifacts for that exact run ID and executes `verify_phase0_downloaded_run.py`. The verifier requires:

- gate-ready hosted summary
- repository, workflow run ID/URL, full 40-character commit SHA, and Git ref metadata
- independently valid Android build evidence
- independently valid Android launch evidence
- independently valid iOS build evidence
- independently valid iOS launch evidence
- the recomputed APK, iOS archive, Android screenshot, and iOS screenshot SHA-256 values to appear in the hosted summary

A successful verification writes a JSON and Markdown run record. `record_phase0_hosted_run.py` can insert that verified record into this document idempotently; it never changes task status automatically.
